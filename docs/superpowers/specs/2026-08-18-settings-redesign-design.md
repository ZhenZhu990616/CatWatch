# CatWatch 设置窗口重设计规格

**状态：** 已确认
**日期：** 2026-08-18
**范围：** 仅设置窗口及其设置应用机制

## 目标

将 CatWatch 当前的设置窗口重构为更符合原生 macOS 与 SwiftUI 审美的分栏卡片式界面，并把手动保存改为安全的即时保存。重构同时拆解过大的设置文件、消除重复状态同步，并避免一次设置修改触发无关运行时模块重载。

## 已确认的产品决策

- 只重做设置窗口；菜单栏菜单、截图、框选层、回答悬浮窗和 Touch Bar 不改版。
- 采用“原生分栏 + 分组卡片行”方案，不自绘窗口框架。
- 界面跟随系统浅色、深色和高对比度外观，不强制深色主题。
- 保留全部现有设置能力，但允许重新排序、分组和优化说明文字。
- 设置修改后即时保存并生效，移除底部保存栏和关闭窗口时的未保存确认。
- 侧栏不显示额外的 “CatWatch” 品牌标题；系统窗口标题仍为“CatWatch 设置”。
- 侧栏保持紧凑，宽度范围为最小 148 pt、理想 160 pt、最大 176 pt。
- 右侧卡片继续铺满可用内容区，不设置单独的最大宽度。

## 当前代码审计

### 主要问题

1. `Sources/SettingsWindowController.swift` 同时承担窗口管理、状态模型、五个页面、通用控件和 AppKit 快捷键录制，文件超过 1100 行。
2. `SettingsViewModel` 使用约 30 个独立的 `@Published` 字段，初始化、重新载入、保存和脏状态检查重复列举相同字段。
3. 设置保存统一调用 `reloadRuntime()`，会同时处理面板、账号菜单、快捷键和 LLM 客户端；局部设置可能触发无关工作。
4. 当前 `Form + SaveBar` 难以实现参考界面的连续卡片层次，也让设置必须经过第二次保存操作。
5. 数字字段依赖结束编辑才提交，当前关闭确认需要额外调用 `makeFirstResponder(nil)`，增加了状态遗漏风险。

### 保留的良好实现

- 继续使用 `NavigationSplitView`、系统 `NSWindow` 和 `NSHostingController`。
- 继续使用 `ConfigDraft` 作为持久化设置的完整快照。
- 保留快捷键录制的 AppKit 桥接、登录/权限动作、预设存储和窗口位置恢复。
- 保留现有运行时安全措施，包括 OAuth 会话代际、旋转 refresh token、截图取消和悬浮窗材质兼容修复。

## 视觉与布局

### 窗口

- 使用标准有标题栏的 macOS 设置窗口，保留交通灯、系统阴影、缩放和位置恢复。
- 默认内容尺寸约为 880 × 620 pt。
- 最小尺寸约为 760 × 520 pt，确保侧栏和尾部控件不会互相挤压。
- 使用 unified 标题栏风格；窗口标题保持“CatWatch 设置”。

### 侧栏

侧栏直接从分组标题开始，不显示品牌标题：

1. **工作流**
   - 快捷键
   - 提示词
2. **智能**
   - 模型
3. **应用**
   - 外观
   - 服务

侧栏使用系统 source list 行为、SF Symbols 和强调色选中态。分组标签采用次要语义颜色，选中行使用系统 accent color，不硬编码蓝色。

### 详情页

每个页面使用相同结构：

- 顶部是 20–22 pt 页面标题和一句简短说明。
- 页面主体使用垂直 `ScrollView`。
- 每个功能组由 12 pt semibold 分区标题和一个连续圆角卡片组成。
- 卡片内部是设置行，标题与说明在左，控件在右；相关行之间使用内缩分隔线。
- 设置行最小高度为 52 pt，卡片圆角约 10–12 pt。
- 卡片铺满详情区可用宽度；窗口比例由默认尺寸和最小尺寸控制。
- 不显示固定底部保存栏。

### 颜色与材质

- 所有文字使用 `.primary`、`.secondary` 等语义样式。
- 卡片与侧栏使用系统 Material 和语义背景色，不复制参考图的固定黑灰色值。
- macOS 26 及以上可在导航 chrome 使用 Liquid Glass；macOS 13–15 使用 `.regularMaterial` 或同等原生材质回退。
- 主要内容区保持清晰，不在密集设置卡片上叠加过强玻璃效果。
- 高对比度模式下分隔线和次要文字仍需可辨认。

## 页面内容

### 快捷键

- **全局操作卡片：** 立即截图、框选截图、显示/隐藏结果。
- **固定截图区域卡片：** 启用开关、坐标摘要、从屏幕选择按钮。
- 页面标题区提供次要的“恢复默认快捷键”动作，替代原保存栏中的同名按钮。
- 快捷键录制完成后立即验证和注册。

### 提示词

- **预设卡片：** 显示现有预设、使用动作、删除动作，以及“把当前提示词存为预设”。
- **默认提示词卡片：** 多行编辑器和用途说明。
- **系统指令卡片：** 多行编辑器和 Responses `instructions` 说明。
- 预设的添加、删除和应用继续即时执行。

### 模型

- **模型卡片：** 模型 ID、快捷模型菜单、Thinking 开关、智能程度、思考摘要。
- **输出卡片：** 输出详略、服务层级、输出 token 上限、图片最大边长。
- 依赖 Thinking 的控件继续在关闭时禁用。

### 外观

- **回答显示卡片：** 悬浮窗/Touch Bar 分段选择。
- 悬浮窗模式显示背景透明度、文字透明度、字体大小、文字颜色和尺寸说明。
- Touch Bar 模式显示字号、文字强度、文字颜色和对齐方式。
- 本机没有 Touch Bar 时继续显示回退提示。
- 外观滑块改变时实时更新对应输出视图。

### 服务

- **Codex 账号卡片：** 登录状态、登录/重新登录、退出登录。
- **权限卡片：** 屏幕录制状态和打开系统设置动作。
- **运行卡片：** 当前状态、快捷键状态、开机自启。
- **关于卡片：** 版本和运行方式。

## 即时保存与运行时应用

### 状态模型

`SettingsViewModel` 维护两份状态：

- `draft`：窗口中当前正在编辑的值。
- `lastAppliedDraft`：最后一次通过验证、已持久化并应用到运行时的值。

设置控件通过带作用域的 `Binding` 修改 `draft`，不再为每个字段重复声明加载、保存和脏检查代码。

### 更新作用域

每次有效修改都会保存完整 `ConfigDraft`，但只执行对应的运行时动作：

- `appearance`：仅重新配置悬浮窗或 Touch Bar。
- `shortcuts`：仅重新注册全局快捷键并更新菜单显示。
- `client`：更新模型、推理、输出、默认提示词或系统指令，并重建 LLM 客户端。
- `storageOnly`：更新固定截图区域、面板几何等在下一次使用时读取的设置，不重载其他模块。

登录、退出登录、屏幕权限、开机自启和预设存储继续使用各自现有的动作接口，不经过通用配置作用域。

### 应用时机

- 外观滑块和分段控件实时应用。
- 快捷键在录制完成后一次验证和应用。
- 模型 ID、默认提示词和系统指令等文本输入在停止输入约 300 ms 后验证、保存和应用，避免每次按键都重建客户端。
- SwiftUI 数字字段在有效值提交到绑定时立即应用。

### 验证与错误

- 正常保存不显示持续性的“已保存”提示。
- 模型 ID 为空或其他文本配置无效时，保留当前编辑内容并在对应设置行显示错误；不持久化，也不覆盖 `lastAppliedDraft`。
- 快捷键格式无效或注册冲突时，恢复上一个可用快捷键，并在对应行显示原因。
- 开机自启、登录和权限错误继续在相关卡片内显示，不使用全局模态警告代替可恢复的行内错误。
- 关闭设置窗口不再进行未保存检查；未通过验证的临时文本不会成为下次启动配置。

## 代码结构

现有单文件设置实现拆分到 `Sources/Settings/`：

- `SettingsWindowController.swift`：窗口创建、位置恢复和生命周期。
- `SettingsViewModel.swift`：草稿、验证、即时保存、更新作用域与错误状态。
- `SettingsRootView.swift`：`NavigationSplitView`、侧栏分组和详情路由。
- `SettingsComponents.swift`：页面标题、分区、卡片、设置行和行内状态组件。
- `ShortcutsSettingsView.swift`：快捷键和固定截图区域。
- `PromptSettingsView.swift`：预设、默认提示词和系统指令。
- `ModelSettingsView.swift`：模型、Thinking 和输出选项。
- `AppearanceSettingsView.swift`：悬浮窗和 Touch Bar 外观。
- `ServiceSettingsView.swift`：账号、权限、运行和关于。
- `ShortcutRecorder.swift`：`NSViewRepresentable` 与 `ShortcutCaptureButton`。

`Sources/main.swift` 中的设置应用入口拆为可独立调用的外观、快捷键、客户端和纯存储更新。现有截图、OAuth、历史记录和回答显示流程不搬迁、不重写。

## 测试策略

### 自动化测试

- `SettingsViewModelTests`：验证有效修改即时持久化、文本修改去抖、无效值不覆盖有效配置、关闭窗口无需保存。
- `SettingsApplicationTests`：验证每类字段映射到正确的更新作用域，外观修改不会注册快捷键，快捷键修改不会重建客户端。
- `ShortcutSettingsTests`：验证无效格式和冲突恢复上一个可用值。
- 保留并运行 `ConfigDefaultsTests` 与 `ResultPanelCompatibilityTests`。

测试通过依赖注入的持久化和运行时应用接口观察真实状态转换，不直接写用户的 `UserDefaults` 或钥匙串。

### 视觉与构建验证

- 使用 `CATWATCH_OPEN_SETTINGS` 分别打开五个分区检查布局。
- 在浅色、深色和提高对比度模式下检查语义颜色。
- 检查默认窗口、最小窗口和扩大窗口；侧栏宽度保持 148/160/176 pt 约束。
- 验证所有控件可通过键盘导航，图标和自定义快捷键录制器具有辅助功能标签。
- 运行完整 Debug 测试和 Release 构建。
- 用 Mach-O build version 检查最终二进制最低系统版本仍为 macOS 13.0。

## 非目标

- 不重设计菜单栏菜单、截图框选层、回答悬浮窗或 Touch Bar 内容布局。
- 不修改 Codex API 请求、SSE 解析、OAuth 流程或钥匙串格式。
- 不新增云同步、导入导出、历史记录管理窗口或主题选择设置。
- 不强制应用使用深色模式。

## 验收标准

1. 设置窗口采用已确认的紧凑侧栏和铺满内容区的卡片布局。
2. 侧栏不显示 “CatWatch” 品牌标题，系统窗口标题保持不变。
3. 五个分区包含全部现有设置能力，没有功能丢失。
4. 设置修改无需保存按钮即可安全持久化并按作用域生效。
5. 无效输入不会破坏最后一个可用运行时配置。
6. 外观、快捷键和客户端设置互不触发无关模块更新。
7. 浅色、深色、高对比度与 macOS 13–27 的材质回退保持可读。
8. 设置实现拆分为职责明确的文件，原 1100 行以上单文件不再承载全部界面。
9. 新增测试与现有测试全部通过，Release 构建成功。
10. 最终二进制最低系统版本仍为 macOS 13.0。
